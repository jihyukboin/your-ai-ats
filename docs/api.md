# 개발자 포트폴리오 플래너 API 명세

서버 기본 주소는 `http://127.0.0.1:8000`이다. 실행 중인 서버의 `/docs`에서 각 요청을 보낼 수 있으며 `/openapi.json`에서 전체 서비스의 OpenAPI 스키마를 받을 수 있다. 아래 경로의 공통 접두사는 `/api/planner`이다. 로컬 단일 사용자 서비스를 전제로 하며, 대화의 `session_id`는 맥락과 로그를 묶는 식별자다.

| 메서드와 경로 | 입력 | 정상 응답 |
| --- | --- | --- |
| `GET /tools` | 없음 | 200. 이름, 설명, 외부 API 구분, 입력·출력 JSON Schema 목록 |
| `POST /chat` | `message`와 선택적 `session_id` | 200. 세션 및 실행 식별자, 상태, 답변, 저장 가능한 계획 제안 또는 `null`, 순서가 있는 실행 이벤트 |
| `GET /plans` | 없음 | 200. 날짜와 시작 시간 순으로 정렬한 계획 배열 |
| `POST /plans` | 계획 입력 전체 | 201. 저장한 `plan`과 같은 날짜에 시간이 겹치는 기존 계획 배열 `overlaps` |
| `GET /plans/{plan_id}` | 계획 ID | 200. 계획 1건 |
| `PUT /plans/{plan_id}` | 계획 ID, 계획 입력 전체 | 200. 수정한 `plan`과 `overlaps` |
| `DELETE /plans/{plan_id}` | 계획 ID | 204. 응답 본문 없음 |
| `GET /logs` | 없음 | 200. 세션별 `session_id`, `run_count`, `event_count`, `updated_at` 배열, 최근 이벤트 순 |
| `GET /logs/{session_id}` | 세션 ID | 200. `session_id`, 실행 시간 순의 `runs` 배열 |
| `DELETE /logs/{session_id}` | 세션 ID | 204. 해당 세션의 전체 실행 기록 삭제 |

실제 서버에서 표시한 플래너 경로는 [FastAPI 문서 화면](evidence/api.png)에서 확인할 수 있다.

## 대화

`message`는 공백 제거 후 1~4,000자이며, 세션 ID는 영문·숫자·밑줄·하이픈 1~100자다. 생략하면 서버가 UUID를 발급한다. 다음 요청에서 같은 ID를 보내면 저장된 맥락을 사용한다.

```json
{"session_id":"portfolio-demo","message":"내일 14시부터 15시까지 Python 입문 이슈 추천해 줘"}
```

`status`는 `recommended`(추천), `no_match`(적합 후보 없음), `clarify`(추가 조건 필요), `help`(도움말), `error`(요청 처리 실패) 중 하나다. `answer`는 사용자에게 보여 줄 한국어 답변이다. `proposal`이 있으면 아래 계획 입력과 같은 형식으로 `POST /plans`에 넘길 수 있다. 실행당 고유한 `run_id`와 해당 실행의 `events`가 함께 반환된다. 조건은 `conditions`, 원문 링크와 저자 정보는 `sources`, 제외한 후보와 이유는 `excluded`, 재계획 횟수는 `replans`에 담는다. 내부의 대화 맥락은 SQLite에 보관한다.

이벤트에는 `session_id`, `run_id`, `seq`(1부터 시작), `at`(UTC ISO 8601), `type`, `stage`, `data`가 들어간다. 실행 도중 들어온 이벤트는 순서대로 저장된다. 세션 상세의 각 실행에는 `run_id`, `started_at`, `message`, `answer`, `status`, `proposal`, `sources`(원문 출처), `events`가 포함된다. 아직 완료되지 않은 실행은 최종 답변과 상태가 `null`일 수 있다.

로그에는 목록·상세 조회와 삭제만 제공한다. 같은 세션을 삭제하면 기록 전체가 제거되고, 다음 요청부터 새 로그가 쌓인다. 사용자의 진행 중인 작업을 이어갈 수 있도록 대화 맥락과 저장한 계획은 별도 테이블에서 관리한다. 로깅 Agent가 연결되지 않거나 저장에 실패해도 대화 응답 자체에는 해당 실행의 이벤트가 포함된다.

## 계획 저장과 수정

다음은 요청 형식을 보여 주는 예시다. 날짜와 시간은 한국 현지 달력 기준이다.

```json
{
  "title": "Python 입문 이슈 본문 검토",
  "date": "2026-11-20",
  "start_time": "14:00",
  "end_time": "14:30",
  "notes": "문제와 댓글을 읽고 작업 범위를 정리한다.",
  "url": "https://github.com/example/project/issues/1"
}
```

제목은 공백 제거 후 1~500자다. 날짜는 `YYYY-MM-DD`, 시각은 24시간제 `HH:MM` 형식이며 종료 시각은 같은 날의 시작 시각보다 늦어야 한다. `notes`는 선택적 문자열(최대 8,000자), `url`은 선택적 HTTP(S) 주소다. 응답의 계획에는 서버가 생성한 `id`, `created_at`, `updated_at`이 추가된다.

시간 겹침은 같은 날짜에서 `기존 시작 < 새 종료`이고 `기존 종료 > 새 시작`일 때 성립한다. 14:00~14:30 계획과 14:30~15:00 계획은 연속해서 저장할 수 있고 `overlaps`는 빈 배열이다. 저장·수정과 겹침 조회를 하나의 SQLite 트랜잭션에서 수행한다.

## 오류

| HTTP 상태 | 발생 조건 |
| --- | --- |
| 404 | 요청한 계획 또는 실행 로그 없음 |
| 405 | 실행 로그 수정 등 지원하지 않는 메서드 |
| 409 | 같은 세션의 맥락이 다른 서버 프로세스에서 먼저 갱신됨. 변경된 조건으로 다시 요청 |
| 422 | 날짜·시간·필수 입력·식별자 형식 오류 |
| 500 | 그래프 실행 중 처리할 수 없는 오류. 일반화한 안내를 반환 |

외부 API 호출이 실패한 경우는 Tool의 구조화된 실패 정보로 처리한다. 부분 실패를 포함한 플래너 실행 결과는 정상적으로 생성될 수 있으므로 호출자는 HTTP 상태와 대화 상태를 함께 확인한다.
